# 提示词模板

复制对应章节的「提示词」代码块。先填 `{{变量}}`，再整段发送。
变量不知道就写「未知，请先从仓库推断」，不要删掉那一行。

---

## 01 冷启动 — 立项与宪法

**何时：** 空仓库，或旧项目第一次交给 AI 长期维护。
**产出：** `AGENTS.md`（若无）、`docs/project-map.md`、必要的 ADR、目录骨架。不写业务功能。

```
你在为一个会维护数年的项目做冷启动，不是写 Demo。

## 项目
- 名称：{{NAME}}
- 一句话做什么：{{PURPOSE}}
- 谁在用、怎么交付：{{USERS_AND_SHIP}}
- 硬约束（合规/性能/离线/平台）：{{CONSTRAINTS}}
- 明确不做：{{NON_GOALS}}

## 你必须完成
1. 写出项目宪法（10 条以内，可执行，禁止空话）。
2. 画出模块边界：每个模块的职责、公开入口、禁止依赖谁。
3. 选定最小技术栈，并写 ADR：为什么选、为什么不选备选。
4. 列出目录骨架（空实现可以，但每个目录要有存在理由）。
5. 写出 3 个核心不变量，以及每个不变量的最小验证方式。
6. 把以上写入 docs/project-map.md；不可逆选择写入 docs/adr/。

## 禁止
- 不要实现第一个功能。
- 不要引入「以后可能用到」的框架、中间层、配置中心。
- 不要写超过一页的愿景文。地图必须能在 3 分钟内读完。
```

## 02 架构 — 边界与契约

**何时：** 新子系统、切开旧模块、替换存储/协议/通信方式。
**产出：** 一张边界图（文字即可）、契约、一篇 ADR。代码只允许改边界所必需的那一层。

```
本次只做架构决策，不夹带功能实现。

## 要解决的问题
{{PROBLEM}}

## 现状
- 相关模块：{{MODULES}}
- 当前痛点（用事实，不用感受）：{{PAIN}}
- 调用量级 / 数据量 / 延迟要求：{{SCALE}}

## 请给出
1. 2 个可行方案，每个包含：模块怎么切、数据怎么流、失败怎么表现。
2. 推荐其中一个，用「不可逆成本」而不是「优雅」来辩护。
3. 公开契约：输入、输出、错误、幂等、超时。
4. 允许依赖表与禁止依赖表。
5. 迁移步骤：每步可单独合入、可回滚。
6. 写成 docs/adr/{{NNNN}}-{{slug}}.md，并更新 docs/project-map.md。

## 约束
- 若现有模块已能覆盖，推荐「不切开」，并说明阈值（什么信号出现才该切）。
- 不要引入新的间接层，除非没有它契约无法稳定。
```

## 03 实现 — 垂直切片

**何时：** 需求清楚，边界已在地图里。做一块用户可感知的完整切片。
**产出：** 最小实现 + 钉住不变量的检查 + 地图上相关条目的更新。

```
按现有模块边界实现一个垂直切片。一次只交付这一个意图。

## 切片
- 用户可感知的完成定义：{{DONE}}
- 所属模块与入口：{{MODULE_AND_ENTRY}}
- 不改的模块：{{OUT_OF_SCOPE}}
- 必须遵守的不变量：{{INVARIANTS}}
- 验收：{{ACCEPTANCE}}

## 实现纪律
1. 先指出将改的文件清单（不超过必要数量），再写代码。
2. 跨模块只走公开入口；需要新入口时先把契约写进地图。
3. 错误在信任边界上校验；内部假设用断言或测试钉住。
4. 留下一个最小可运行检查（测试或自检），让「逻辑坏了会红」。
5. 不要加功能开关、不要加「将来扩展点」、不要抽只有一处调用的接口。

## 完成后用四行汇报
意图 / 改了什么 / 没改什么 / 如何验证。
```

## 04 变更 — 日常最小 diff（默认用这条）

**何时：** 修 bug、改一处行为、加一个窄功能。这是长期维护的主路径。
**产出：** 小 diff、验证、必要时两行地图更新。

```
这是一次增量变更。按最小合入 diff 执行。

## 变更
- 意图：{{INTENT}}
- 现象或需求：{{SYMPTOM_OR_NEED}}
- 建议落点（可被你推翻）：{{HINT_PATH}}
- 禁止事项：{{FORBIDDEN}}

## 动手前先写四行
1. 意图
2. 模块（改 / 不改）
3. 风险（可能破坏的不变量）
4. 验证（命令或检查）

## 执行
- 只改与意图直接相关的代码。
- 发现必须扩大范围：停止，说明原因，等待确认。
- 修 bug：先复现，再改，再用同一路径验证。
- 不要顺手格式化无关文件，不要升级无关依赖。
- 行为有变就更新地图或 ADR 里对应的那一句。
```

---

## 05 审查 — 可维护性，不只是正确性

**何时：** 合并前。审查对象可以是 diff、分支或某个模块。
**产出：** 按阻塞/应改/可忽略分级的意见。不直接大改代码，除非被要求修复。

```
做可维护性代码审查。默认只给意见，不要顺便重写。

## 审查范围
{{RANGE}}  （例如：当前 diff / 某模块 / 某 PR 描述）

## 按这个顺序看
1. 边界：是否跨模块偷依赖、是否把临时逻辑写进了核心。
2. 意图密度：这个 diff 是否夹带第二个意图。
3. 不变量：协议/状态/失败路径有没有被测试或自检钉住。
4. 删除空间：有没有可删的抽象、配置、重复、死代码。
5. 命名与入口：三个月后能否从地图找到这段代码。
6. 运维：日志、错误信息、回滚是否够用（只看本次改动相关的）。

## 输出格式
- 阻塞：不修不能合。每条指出文件、问题、最小修法。
- 应改：合入后会疼，但可另开任务。
- 可忽略：风格偏好，不要吵。
- 总结：一句话描述这个 diff 的真实意图，若你读不出来，这本身就是阻塞。

禁止：以「更优雅」为由要求加层；没有调用方的接口一律建议删。
```

## 06 重构 — 行为冻结

**何时：** 结构已经妨碍变更，但行为必须保持。
**产出：** 纯结构 diff + 用旧检查证明行为没变。

```
本次是行为冻结的重构。对外可观察行为必须与现在完全一致。

## 目标
- 重构原因（用即将到来的变更证明必要性）：{{WHY}}
- 范围：{{SCOPE}}
- 冻结的行为与检查：{{CHECKS}}

## 规则
1. 先确保 {{CHECKS}} 在重构前是绿的。没有检查就先补最小检查，再重构。
2. 不允许同时修 bug、改文案、改 API、改配置默认值。
3. 不允许引入新依赖。
4. 每一步都保持可编译、检查为绿。
5. 完成后对照地图，更新模块入口；若边界没变，地图可以只改一句「内部结构」。

若重构的唯一好处是好看：停下来，写「不值得做」并退出。
```

## 07 排障 — 先复现再动手

**何时：** 有故障或异常现象。禁止在没复现时广撒网改代码。
**产出：** 因果链、最小修复、回归检查。

```
排障。在锁定因果之前不要修。

## 现象
- 期望：{{EXPECTED}}
- 实际：{{ACTUAL}}
- 复现步骤：{{REPRO}}
- 最近相关变更：{{RECENT}}
- 环境差异（若有）：{{ENV}}

## 过程
1. 把现象收成一条可证伪命题。
2. 列出 3 个假设，按「便宜能证伪」排序，不要按「像不像」排序。
3. 一次只检验一个假设；用日志、断言或最小复现证明。
4. 定位到具体模块与不变量后，再做最小修复。
5. 用原来的复现步骤验证；补一个以后会抓住它的检查。

## 禁止
- 禁止「顺便把附近都加固」。
- 禁止在未复现时重构。
- 若无法复现：输出还缺什么信息，而不是猜测补丁。
```

## 08 交接 — 压缩上下文给下一个会话

**何时：** 长任务要跨会话、换模型、或上下文已经脏了。
**产出：** 一份下一会话可以直接粘贴的接力提示（同时写入 `docs/handoff.md`）。

```
把当前工作压缩成下一会话的唯一入口。假设下一会话没有本对话记忆。

## 已知
- 目标：{{GOAL}}
- 已完成：{{DONE}}
- 未完成：{{TODO}}
- 踩过的坑：{{PITFALLS}}
- 关键文件：{{FILES}}

## 请写出 docs/handoff.md，包含且只包含
1. 一句话当前状态。
2. 下一步唯一动作（只要一个）。
3. 必须先读的文件（最多 5 个）及为什么读。
4. 已锁定的决策（不要重新讨论）。
5. 仍开放的问题（不要假装已决）。
6. 验证命令。
7. 给下一会话的提示词（可直接粘贴，80 行以内）。

写完后停止。不要继续实现。
```

## 09 技术债 — 盘点而不是抒发

**何时：** 感觉乱了、依赖多了、改一处炸三处。先盘点再决定动哪一块。
**产出：** 按「阻碍下次变更」排序的清单，最多 5 项动手建议。

```
做一次技术债盘点。目标是让下一次变更更便宜，不是写控诉信。

## 焦点
{{FOCUS}}  （模块 / 依赖 / 测试 / 构建 / 全局）

## 请扫描并只报告
1. 跨边界依赖（谁不该认识谁，却认识了）。
2. 没有调用方的抽象、重复的封装、死代码。
3. 无版本钉死或不必要的第三方依赖。
4. 核心不变量没有检查。
5. 地图/ADR 与代码不一致的地方。

## 输出
- 最多 5 个条目。每条：位置、它让哪次变更变贵、最小处理、不处理的后果。
- 明确「现在不要动」的部分及原因。
- 若只有风格问题：说「没有值得现在还的债」。

禁止列 20 条愿望清单。禁止建议重写。
```
