# 提示词怎么用

每条模板都是完整提示词。把 `{{花括号}}` 换成当前任务，整段贴给 AI。

| 场景 | 模板 | 何时用 |
|---|---|---|
| 立项 / 空仓库 | `01-bootstrap` | 还没有模块图、还没定技术边界 |
| 切模块 / 定契约 | `02-architecture` | 要新增子系统、切开边界、选存储或协议 |
| 做新功能 | `03-implement` | 需求清楚，按现有边界做垂直切片 |
| 日常改动 | `04-change` | **最常用**。修一小块、加一个开关、改一处行为 |
| 审查 | `05-review` | 合并前看可维护性，不只看「能不能跑」 |
| 重构 | `06-refactor` | 行为必须保持，只动结构 |
| 排障 | `07-debug` | 有可复现现象，禁止先改一通碰运气 |
| 换会话 / 长期接力 | `08-handoff` | 当前上下文要扔掉，留给下一个会话 |
| 技术债盘点 | `09-debt` | 依赖膨胀、模块腐烂、测试空心时 |

配套活文档（不是提示词，是仓库里持续改的文件）：

- `docs/project-map.md` — 模块地图，从 `docs/project-map.template.md` 复制
- `docs/adr/` — 决策记录，从 `docs/adr/template.md` 复制
