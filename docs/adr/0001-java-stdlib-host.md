# ADR 0001: Java 17 + JDK 标准库做 Host

- 状态：已接受
- 日期：2026-08-22

## 背景

仓库在 `javaProject` 下。使用者是作者本人，交付物是 Windows 上能打开 `.nes` 并稳定约 60 帧。需要窗口、按键、音频，不需要安装第二套工具链才能开写。

## 决策

用 **Java 17**（LTS）写全部模块。窗口与帧缓冲用 **AWT / Java2D**（`BufferedImage` + 窗口）。音频用 **`javax.sound.sampled`**。构建用 **Maven，运行时零依赖**。

## 没选

- **C + SDL**：60 帧天花板更高，但要维护第二语言和本地库，和当前仓库、作者习惯不一致。
- **LWJGL / libGDX / JavaFX**：没有它们也能把 256×240 贴到窗口并出声；多一个依赖换不到现在做不到的事。
- **Kotlin / Rust**：多一套语言与构建，冷启动用不上。

## 后果

- 从此必须遵守：新库必须先能指出「标准库做不到的那一件事」，再写 ADR。
- 从此变贵的事：要极致周期精度又要很低延迟音频时，Java 可能先碰到天花板。
- 推翻阈值：在 **NROM 能跑的游戏上，本机测不到稳定约 60 帧**（实现已按周期模型、不是算法烂）时，重开：本地代码或换 Host 层。
