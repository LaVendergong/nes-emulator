# ADR 0002: NTSC + 按周期推进

- 状态：已接受
- 日期：2026-08-22

## 背景

FC/NES 能否稳定出画，取决于 CPU 与 PPU 的固定比例。先写「按扫描线估一帧」再改周期精确，等于重写 PPU 和所有时序游戏。

## 决策

推进单位是 **CPU cycle**，不是扫描线估算。NTSC/Dendy：1 CPU = 3 PPU dots。PAL 的 5:16 与 312 线见 [ADR 0004](0004-pal-ym2413.md)。APU 跟同一条主时钟。Host 可以用墙钟限速，内部时间只认 NES 时钟。

## 没选

- **先扫描线、以后再周期**：短期少代码，不可逆成本是 PPU 与 mapper IRQ 整核重写。
- **当时不做 PAL**：已被 [ADR 0004](0004-pal-ym2413.md) 在同一套周期核上补上；本 ADR 仍管「按 cycle 推，不按扫描线估」。
- **用墙钟驱动 CPU**：暂停/卡顿会快进或拖步，和「稳定 60 帧」冲突。

## 后果

- 从此必须遵守：禁止出现「一帧直接画完 nametable」而不走 dot 计数的实现。
- 从此变贵的事：第一条能显示的图也会比扫描线原型慢写。
- 推翻阈值：测出 Java 周期循环本身达不到 60 帧，再重开（降精度或换语言）。PAL/Dendy 已由 ADR 0004 补上，不再用本条挡。
