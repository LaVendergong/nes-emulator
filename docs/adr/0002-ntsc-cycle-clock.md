# ADR 0002: NTSC + 按周期推进

- 状态：已接受
- 日期：2026-08-22

## 背景

FC/NES 能否稳定出画，取决于 CPU 与 PPU 的固定比例。先写「按扫描线估一帧」再改周期精确，等于重写 PPU 和所有时序游戏。

## 决策

只做 **NTSC**。推进单位是 **CPU cycle**：每 1 个 CPU cycle，PPU 走 **3 dots**，APU 跟同一条主时钟。Host 可以用墙钟把输出限制在约 60 Hz，但模拟器内部时间只认 NES 时钟。

## 没选

- **先扫描线、以后再周期**：短期少代码，不可逆成本是 PPU 与 mapper IRQ 整核重写。
- **默认 PAL / 双制式**：用户场景是 FC/NES 常见 NTSC 游戏；双制式会分叉每一条时序不变量。
- **用墙钟驱动 CPU**：暂停/卡顿会快进或拖步，和「稳定 60 帧」冲突。

## 后果

- 从此必须遵守：禁止出现「一帧直接画完 nametable」而不走 dot 计数的实现。
- 从此变贵的事：第一条能显示的图也会比扫描线原型慢写。
- 推翻阈值：要正式支持 PAL 软件标题，或测出 Java 周期循环本身达不到 60 帧，再重开（PAL 分叉或降精度）。
